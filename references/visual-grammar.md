# 视觉图法

图法只决定“用什么结构让读者看懂原文关系”。根据原文已有关系选择一种主图法；视觉风格只能改变呈现，不能创造或改变关系。

| grammar | 适用于 | 不适用于 |
| --- | --- | --- |
| `architecture` | 组件、依赖、分支、合并、上下游 | 纯时间步骤、父子分类 |
| `hierarchy` | 父子关系、类别与子类、整体与部分、组织层级 | 条件选择、时间顺序、系统依赖 |
| `flow` | 有先后顺序的步骤、输入到输出 | 没有顺序的并列概念 |
| `loop` | 反馈、迭代、优化、约束、重复循环 | 一次性路线 |
| `decision_tree` | 条件选择、如果/那么、分叉路径 | 没有决策条件的组件依赖 |
| `comparison` | 两个或多个方案的差异和取舍 | 单一过程 |
| `matrix` | 两个独立维度下的分类、定位、术语区分 | 单维分类、细致时间变化 |
| `overlap_map` | 共同部分、差异、交集、共存、冲突 | 互斥选项、顺序过程 |
| `boundary_map` | 什么属于、什么不属于、它不是什么 | 操作步骤 |
| `argument_map` | 已有主张、已陈述依据、限制、结论 | 编造证据、无依据因果 |
| `timeline` | 历史、阶段、真实时间推进 | 同时存在的系统结构 |
| `continuum` | 渐进位置、成熟度、强度、非时间光谱 | 真实时间进程 |
| `layer_stack` | 抽象层、系统层、包含关系 | 密集方向依赖、父子分类 |

## 容易混淆的图法

- 组件如何连接用 `architecture`；父子或分类关系用 `hierarchy`；只有明确条件选择路径时才用 `decision_tree`。
- 一次性步骤用 `flow`；真实时间推进用 `timeline`；重复反馈用 `loop`。
- 方案权衡用 `comparison`；同一对象被两个独立维度分类时用 `matrix`；交集或共存用 `overlap_map`。`comparison` 必须保留至少两项原文支持、遮住标签仍可看出的左右差异；其中至少一项必须是对象、位置、连接、顺序或边界的不同，不能只换名称。
- 非时间的成熟度或强度变化用 `continuum`；不要擅自暗示时间流逝。
- `argument_map` 只能整理原文或真实来源已经提供的主张、依据、限制和结论。

## 选择与保存

- 每张图只选择一种主图法。辅助结构可以嵌套在主结构内部，但不能形成第二个视觉中心。
- `grammar` 保存主图法；`must_show` 保存必须保留的原文细节和关系拓扑。
- 当 `grammar` 是 `comparison`，`comparison_basis` 保存左右各自的可见差异条件；没有可见差异条件时，不要生成对比图。
- 在内部比较可能混淆的备选图法，但 manifest 只保存最终选定的 `grammar`。
- 不要把所有概念都变成圆圈箭头，不要添加装饰性因果，也不要把不同关系强塞进同一模板。

## 真实来源图

`annotated_source` 是素材处理方式，不是图法。使用已提供的真实截图、论文图、数据图或 UI 图时，在 plan 中写 `source_mode: annotated_source` 和可解析的 `source_asset`，同时仍要选择表达其关系的 `grammar`。必须把结果视为编辑标注，不能伪造截图、来源或事实证据。
